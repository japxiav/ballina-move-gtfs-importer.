# Prepared walking and realtime — not public integration

Pure offline/server inspection modules; no network/importer/collector/database activation. The existing public schedule DTO keeps walkingIncluded=false and realTimeApplied=false. The16-module experimental engine and A12 remain unchanged. These files are not served by the gateway.

Walking accepts bounded open-data topology and computes an explicit last-mile path with Dijkstra. It refuses private/conditional/inaccessible topology, including conditional nodes and unsupported directional ways, bounds nodes/references/work/snap distance and reports disconnected/missing geometry rather than drawing a geodesic substitute. Every result has walkingSafe/publicEligible/physicalEntranceVerified/accessibilityVerified=false, even if a caller supplies a forged verification flag. Connectors and crossing delay remain unverified; zero mapped crossings does not mean zero actual crossings. Entrance tags in the area do not prove association with Mayo Hospital. Distance-only walking seconds are an estimate, not a boarding/safeETA guarantee. Ballina→Hospital whole-trip walking exceeds this2km last-mile scope.

Fixed manual OpenStreetMap reader is dry-run by default, at most1publicbounded request with DNS-inclusive process watchdog, no paid routing provider. It strips editor usernames/IDs/contact metadata and keeps only topology/tags; ODbL attribution for actual captures, fixture license for offlineXML. The actual API request did not become available in this environment. The added domain is saved only in the environment draft and not assumed active. Synthetic fixture paths/crossings/entrance at official NTAendpoint coordinates are explicitly NOT real OSM/access evidence.

Realtime assessment requires exact feed/service-date/trip/route/mode plus boarding/alighting stop and sequence for predictions. It keeps programmed seconds untouched, tracks original source observation times and never renews them from receipt, GPS proximity or IrishRail train codes. Old/missing/future beyond15s clock tolerance/contradictory data and incomplete namespace remain uncertain. Whole-trip cancellation cannot be inferred from a skipped stop; ambiguous vehicles/ETAs and implausible prediction windows fail closed. Exact fresh vehicle matching supplies position evidence only, never an ETA. Equivalent timestamp formats compare by epoch; identical vehicle evidence picks its latest own observation deterministically. Predictions require the query-date clock (not trip service-date), Europe/Dublin conversion with clock-change fail-closed behavior, and a conservative scheduled-event window (2min early /6h late), as well as the observation-time window. This is not transfer feasibility or proof of actual provider projections. PublicItineraryRealtimeApplied is alwaysfalse: this preparatory assessment is not activation.

Normalized realtime fixtures test the contract; no actual collector projection with complete identity has been validated. A future trusted server normalizer must prove those fields from actual operator/feed provenance (not derive service-date/feed/observedAt from ingestion or accept browser claims), retain separate cancelled-stop vs cancelled-trip semantics and verify connections under delays before promotion. IrishRail reported locations stay separate with unknown observation age.

Mayo analysis: stop15108 /15109 remain different. Historical420 reaches15109 at08:52;420→440 reaches15108 at09:24. The32minute scheduled gap cannot be claimed as a verified walking benefit. Official endpoint geodesic about28.5m says nothing about a safe crossing, entrance, boarding bay or accessibility. No walking result replaces/ranks official journeys.

Required physical evidence: hospital association of entrance, actual traversable path/crossing/curb/lighting/slope/access/boarding, mobility constraints and date/tester consent. Required realtime evidence: actual full normalized source identities/timestamps, conflicts/expiry/operator coverage and connection validity. Neither was fabricated; no passenger readiness claim or production/secret changes.

Independent review produced meaningful RED cases for UTF16/entity bypass, conditional node/directional ways, malformedsourceenum/refcaps, equivalenttimestamp ambiguity, schedule-clock alignment and observation-order determinism. StrictUTF8/NUL/DTD rejection, finite coordinate/ID/reference validation, sanitizedofflinefailures and failclosedconstraints were added; original checks retained.
