## Fixes in SQL

- `get_stop_departures_v2` filters `pickup_type=1`; reservation flags 2/3 are preserved rather than excluded.
- The same RPC detects stale trip-update observations and degrades its confidence when TripUpdates collection is not recently healthy.
- `get_live_vehicles` excludes observations from an inactive GTFS version.
- `finalize_gtfs_import` preserves correct `metadata.active=true` semantics upon promotion; one existing metadata discrepancy was reconciled.
- Before 14-day cascade deletion, `prune_transport_history` archives evidence about realtime stop predictions **and** vehicle GPS sightings, in backend-only tables. These snapshots are *not* proof of real on-time arrivals.
- Four previous SQL function definitions were snapshotted to `transport_function_backups` for a supervised rollback.

Post-release production SQL smoke check: 96 departures checked, 0 no-boarding stop_times; 189 historical prediction keys and 117 vehicle history keys saved. New archive tables are RLS-protected and anon cannot execute capture RPCs. Old GTFS stays in the database as inactive; new active version remains `768b4b82327a1b83eb7f9365e4dd4495417df14163e5980889f0df2b223088d3`.

## Fixes prepared for GitHub importer and API gateway

- `import_gtfs.py`: HTTP `304` conditional validators only reused if the exact last accepted version is still active; a fresh state check guards against 304 after rollback/expired feed.
- Nonmonotonic trip times and departure-before-arrival fail validation before staging.
- Import lease duration increased to 1h vs 45m job timeout.
- `gtfs-import-api` gateway v2: validate RPC input token precedence, cap body size, fixed global and per-IP rate limiting suitable for authorized batch throughput, remove raw Postgres error strings in public responses. **Not deployed**.
- `transport-api` v5: validate actions before rate-limit DB writes; apply global flood limit; prefer CDN IP header; require healthy recent GPS and TripUpdates plus fresh source feed timestamp; check GTFS feed expiry; sanitize public metadata; include Humbert Place among departures. **Deployed**.
- GitHub: importer post-activation check now navigates `health.collector.latest_runs`, verifies both channels, HTTP200, feed version, recent events, complete schema and actual departure API shape. It retries on transient status instead of claiming failure after a single check.
- Separate hourly read-only health workflow; may produce GitHub Actions failure alerts once uploaded. It does not run the importer or change Supabase.
