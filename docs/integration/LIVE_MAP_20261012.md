## Implemented behavior

The English mobile interface adds `#/live`, a responsive Leaflet/OSM map, bus/train filters, Mayo/Ireland views, accessible vehicle list, source-specific details, Ballina departures, refresh and loading/error handling. No vehicle path or movement is fabricated. The journey search remains explicitly synthetic until its separate routing gateway passes release and real-world evidence gates.

`web/server/live_gateway.py` serves the build and a fixed read-only same-origin `/api/live` DTO. It consumes existing public `transport-api` actions and Irish Rail XML with verified TLS through the configured proxy. The server alone reads the already-public publishable key in the tracked health workflow. Browser requests contain no apikey/JWT, private endpoints or user coordinates. Strict DTO whitelists, finite Ireland bounds, XML declaration/structure/service-date checks, one-MiB response caps, fixed four-worker pool, a single nine-second refresh deadline, shared cache/singleflight, no queued retry behind unfinished work, bounded clients and read-only HTTP methods are covered offline.

Bus observation timestamps are actual GPS `position_timestamp`; ingestion/retrieval times never replace them. Stale GPS disappears after 180 seconds. Irish Rail supplies reported coordinates and service date without observation time/precision; both are explicitly unknown, and service date is used only to reject obsolete reports. No GTFS match/boarding/arrival is inferred. A fresh delayed departure prediction survives an old scheduled time; expired prediction reverts to scheduled, departed rows disappear and cancellations remove prediction fields.
