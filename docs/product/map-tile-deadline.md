# Slow map tiles

Unpublished frontend fix stacked on `39f30e6`. A map tile request can remain pending without firing Leaflet's `tileerror`; the previous interface could display “Loading map…” indefinitely. After fifteen seconds of a tile-loading cycle, the interface now explains the delay and directs passengers to the vehicle list or refresh. It does not call a pending request a failed feed, substitute example vehicles or change source timestamps. A later complete tile load clears the delay; new loading cycles and component cleanup clear the prior timer.

Build and 38 desktop/mobile map checks pass, including a stalled-tile replay proving the location list and card remain usable while tiles wait, and that later delivery clears the warning. Two preview checks pass. Public API follow-up separately returned43 official positions with all three source channels ready after an initial20-second timeout; this is not a hosting SLO or a production verification of this new code. Source-tile connectivity for the additional local capture is recorded separately and must not be inferred from offline tile stubs.
