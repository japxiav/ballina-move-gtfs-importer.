# Passenger search: stops and Mayo Hospital

Local candidate based on published source `3a96758b87d33908635f03d2e833cd5742609997`. This change is not a deployment, main merge or regional passenger release.

The default hospital search now compares the exact official stops **15108** (`8490B151081`) and **15109** (`8490B151091`). A place is an explicit association of verified GTFS names, IDs and codes, never a proximity match or a claim about a building entrance. Names, station names and stop codes can be typed; exact-stop selection and swapping remain available. Hospital-origin results also identify the boarding stop.

The retained official capture for **14 October 2026, after 07:55, Ballina Bus Station** reproduces direct **420, 08:00–08:52, stop15109**, and **420→440, 08:00–09:24, stop15108**, including distinct transfer points. Twelve returned alternatives are preserved and ordered by stop arrival, changes and departure; six initially appear. Different endpoints are not treated as equivalent for dominance pruning. Arrival at the building, walking between stops, boarding bays and accessibility remain unverified.

The place identifier stays in the frontend URL only. The gateway receives at most four serial exact-stop queries, each with the existing six validated fields and maximum six results. The implemented hospital comparison uses two requests. A quota response stops the remaining batch. Known partial failures are labelled; schema or feed mismatches clear all results. Navigation aborts pending work and a single 23-second budget covers the complete batch. Detail/back uses a six-entry, fifteen-second memory-only cache; retry bypasses it once and cache hits never renew the original lifetime.

Validation: pinned build and standalone build; 26 new Playwright checks across desktop/mobile, 28 existing official-journey/cold-gateway checks, and two static-preview checks. Added regressions cover first-request quota exhaustion, partial timeout, late completion, navigation abortion, retry/detail/back, feed changes, canonical query order, expiry, clock reversal and cache eviction. The fixture is an explicitly labelled replay of captured official responses, not a live backend/device/accessibility validation. Independent review found and prompted fixes to retry, swap and cache lifetime. No backend routing, collector, credentials, feed activation or A12 changes.
